# Recipe from Fridge

## Описание проекта

**Recipe from Fridge** — это B2C-приложение, которое помогает пользователю подобрать рецепты по продуктам, которые уже есть дома.

Пользователь добавляет продукты из холодильника, а приложение предлагает подходящие рецепты, показывает недостающие ингредиенты и помогает меньше выбрасывать еду.

## Бизнес-модель

**B2C — Business-to-Consumer**

Продукт предназначен для обычных пользователей:

- студентов;
- людей, которые живут одни;
- молодых семей;
- занятых людей, которые хотят быстро готовить дома и экономить на еде.

## Основная идея

Многие люди сталкиваются с ситуацией, когда дома есть продукты, но непонятно, что из них приготовить. Из-за этого продукты портятся, деньги тратятся впустую, а пользователь снова покупает лишнее или заказывает доставку.

**Recipe from Fridge** решает эту проблему: пользователь вводит продукты из холодильника, а приложение предлагает блюда, которые можно приготовить из уже имеющихся ингредиентов.

## Цель проекта

Создать MVP мобильного приложения, которое проверяет главную гипотезу:

> Пользователю полезно приложение, которое подбирает рецепты по продуктам, уже имеющимся дома.

# Практические задания

## [Практическое задание №1 — Elevator Pitch и Lean Canvas](Exercise1/README.md)

В первом задании была сформулирована идея проекта, выбран формат B2C и описана бизнес-модель через Lean Canvas.

**Краткий вывод:**  
Проект решает понятную бытовую проблему: пользователь не знает, что приготовить из продуктов дома. Основная ценность продукта — быстрый подбор рецептов по уже имеющимся ингредиентам.

---

## [Практическое задание №2 — User Stories, MVP, MLP, ФТ и НФТ](Exercise2/README.md)

Во втором задании были определены роли пользователей, составлены User Stories, выполнена приоритизация функционала, а также выделены MVP и MLP.

**Краткий вывод:**  
Главный пользовательский путь MVP — добавить продукты, получить список подходящих рецептов и открыть карточку рецепта. Дополнительные функции вроде напоминаний, избранного и персонализации можно развивать после проверки основной гипотезы.

---

## [Практическое задание №3 — DDD, BDD, Wireframes, API-First](Exercise3/README.md)

В третьем задании приложение было разделено на доменные зоны, описан критический путь пользователя через BDD, подготовлены wireframes и JSON-контракты API.

**Краткий вывод:**  
Проект был разложен на понятные части: пользователь, холодильник, рецепты, подбор рецептов и монетизация. Это помогает связать бизнес-логику, пользовательские сценарии и техническую реализацию.

---

## [Практическое задание №4 — C4 и стек технологий](Exercise4/README.md)

В четвертом задании были подготовлены C4-диаграммы уровня Context и Containers, а также выбран технологический стек для MVP.

**Краткий вывод:**  
Для MVP подходит простая архитектура: мобильное приложение, backend API, база данных, админ-панель и внешние сервисы. Такой подход позволяет быстро запустить первую версию и при необходимости масштабировать продукт.

---

## [Практическое задание №5 — команда, методология и ритуалы](Exercise5/README.md)

В пятом задании был составлен hiring plan, выбрана методология разработки и описаны командные ритуалы.

**Краткий вывод:**  
Для разработки MVP подходит небольшая кросс-функциональная команда и Scrum с двухнедельными спринтами. Такой процесс позволяет регулярно получать работающий результат и быстро реагировать на обратную связь.

---

## [Практическое задание №6 — проектные риски](Exercise6/README.md)

В шестом задании были выявлены ключевые риски проекта, определены их типы, уровни и стратегии реагирования.

**Краткий вывод:**  
Самые важные риски проекта — разрастание функциональности, низкое качество подбора рецептов и сложность ввода продуктов. Чтобы снизить эти риски, MVP должен быть сфокусирован только на основном пользовательском пути.

# Общий вывод по проекту

Проект **Recipe from Fridge** прошел основные этапы предварительного проектирования IT-продукта:

1. Определена бизнес-идея и ценность продукта.
2. Сформированы пользовательские истории и MVP.
3. Описаны доменные зоны, сценарии и API-контракты.
4. Спроектирована архитектура и выбран стек технологий.
5. Сформирована команда и процесс разработки.
6. Проанализированы основные проектные риски.

Главная цель MVP — проверить, действительно ли пользователям удобно и полезно получать рецепты на основе продуктов, которые уже есть дома.
