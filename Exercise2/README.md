# Задание №2

## Проект

**Recipe from Fridge**

## Краткое описание

Recipe from Fridge — это B2C-приложение, которое помогает пользователю подобрать рецепты по продуктам, которые уже есть дома.

Пользователь добавляет продукты из холодильника, а приложение предлагает подходящие рецепты, показывает недостающие ингредиенты и помогает меньше выбрасывать еду.

---

# 1. Роли пользователей

## Основные роли

### 1. Обычный пользователь

Человек, ищущиуй что приготовить из продуктов дома.

Примеры:
- студент;
- человек, живущий один;
- занятый человек;
- молодая семья.

### 2. Экономный пользователь

Пользователь, которому важно не выбрасывать продукты и не покупать лишнее.

### 3. Пользователь с ограничениями в питании

Пользователь, которому важно учитывать ограничения: аллергии, диету, нелюбимые продукты.

### 4. Администратор контента

Человек, который добавляет, проверяет и редактирует рецепты в базе приложения.

---

# 2. User Stories

## Основной путь пользователя

### US-1

Как пользователь, я хочу добавить продукты, которые есть у меня дома, чтобы приложение могло подобрать рецепты из этих продуктов.

### US-2

Как пользователь, я хочу увидеть список рецептов по моим продуктам, чтобы быстро выбрать, что приготовить.

### US-3

Как пользователь, я хочу видеть, каких ингредиентов не хватает для рецепта, чтобы понять, нужно ли идти в магазин.

### US-4

Как пользователь, я хочу открыть подробный рецепт, чтобы увидеть шаги приготовления блюда.

### US-5

Как пользователь, я хочу видеть время приготовления рецепта, чтобы выбрать блюдо, которое подходит мне по времени.

### US-6

Как пользователь, я хочу фильтровать рецепты по времени приготовления, чтобы найти быстрые блюда на 10–30 минут.

### US-7

Как пользователь, я хочу сохранять понравившиеся рецепты, чтобы быстро находить их позже.

### US-8

Как пользователь, я хочу отмечать продукты, которые скоро испортятся, чтобы использовать их в первую очередь.

### US-9

Как пользователь, я хочу получать напоминание о продуктах с истекающим сроком годности, чтобы не выбрасывать еду.

### US-10

Как пользователь, я хочу видеть рецепты с минимальным количеством недостающих ингредиентов, чтобы готовить без лишних покупок.

### US-11

Как пользователь, я хочу указать продукты, которые я не ем, чтобы приложение не предлагало неподходящие рецепты.

### US-12

Как пользователь, я хочу указать аллергию или ограничения в питании, чтобы приложение исключало опасные рецепты.

### US-13

Как пользователь, я хочу составлять список покупок из недостающих ингредиентов, чтобы удобно купить только нужное.

### US-14

Как пользователь, я хочу оценивать рецепты, чтобы приложение лучше понимало мои предпочтения.

### US-15

Как пользователь, я хочу видеть простые рецепты для студентов, чтобы готовить дешево и быстро.

### US-16

Как администратор контента, я хочу добавлять новые рецепты в базу, чтобы пользователи получали больше вариантов блюд.

# 3. Приоритизация User Stories

Для приоритизации используется фреймворк **MoSCoW**:

- **Must have** — обязательно должно быть в продукте.
- **Should have** — желательно добавить.
- **Could have** — можно добавить позже.
- **Won’t have** — не делаем в первой версии.

# 5. Детализация требований

Для детализации выбраны две главные истории из MVP:

1. US-1 — добавление продуктов.
2. US-2 — подбор рецептов по продуктам.

---

## История 1: Добавление продуктов

### User Story

Как пользователь, я хочу добавить продукты, которые есть у меня дома, чтобы приложение могло подобрать рецепты из этих продуктов.

## Функциональные требования

Функциональные требования описывают, что система должна уметь делать.

### ФТ-1

Пользователь может открыть экран добавления продуктов.

### ФТ-2

Пользователь может ввести название продукта вручную.

### ФТ-3

Система предлагает подсказки при вводе названия продукта.

### ФТ-4

Пользователь может выбрать продукт из списка подсказок.

### ФТ-5

Пользователь может добавить выбранный продукт в список “Мои продукты”.

### ФТ-6

Пользователь может удалить продукт из списка “Мои продукты”.

### ФТ-7

Пользователь может редактировать количество продукта.

### ФТ-8

Система сохраняет список продуктов пользователя после закрытия приложения.

### ФТ-9

Если пользователь вводит неизвестный продукт, система показывает сообщение: “Продукт не найден”.

### ФТ-10

Пользователь может перейти от списка продуктов к подбору рецептов.

## Нефункциональные требования

Нефункциональные требования описывают качество работы системы и условия ее работы.

### НФТ-1

Экран добавления продуктов должен открываться не дольше чем за 2 секунды.

### НФТ-2

Подсказки при вводе продукта должны появляться не дольше чем за 1 секунду.

### НФТ-3

Список продуктов должен сохраняться локально или в профиле пользователя.

### НФТ-4

Интерфейс должен быть понятен пользователю без инструкции.

### НФТ-5

Приложение должно корректно работать на актуальных версиях Android и iOS.

### НФТ-6

Данные пользователя должны храниться безопасно.

### НФТ-7

При отсутствии интернета пользователь должен иметь возможность видеть ранее добавленные продукты.

### НФТ-8

Текст и кнопки должны быть читаемыми на экранах смартфонов.

---

## История 2: Подбор рецептов по продуктам

### User Story

Как пользователь, я хочу увидеть список рецептов по моим продуктам, чтобы быстро выбрать, что приготовить.

## Функциональные требования

### ФТ-1

Пользователь может нажать кнопку “Подобрать рецепты”.

### ФТ-2

Система анализирует список продуктов пользователя.

### ФТ-3

Система показывает список рецептов, которые можно приготовить из имеющихся продуктов.

### ФТ-4

Система показывает рецепты, для которых не хватает 1–2 ингредиентов.

### ФТ-5

Для каждого рецепта система показывает название блюда.

### ФТ-6

Для каждого рецепта система показывает время приготовления.

### ФТ-7

Для каждого рецепта система показывает список имеющихся и недостающих ингредиентов.

### ФТ-8

Пользователь может открыть карточку рецепта.

### ФТ-9

В карточке рецепта пользователь видит пошаговую инструкцию приготовления.

### ФТ-10

Если подходящих рецептов нет, система показывает сообщение: “Подходящих рецептов пока нет. Попробуйте добавить больше продуктов”.

## Нефункциональные требования

### НФТ-1

Подбор рецептов должен занимать не больше 3 секунд при стандартном количестве продуктов.

### НФТ-2

Список рецептов должен быть отсортирован по совпадению с продуктами пользователя.

### НФТ-3

Интерфейс списка рецептов должен быть удобен для использования на смартфоне.

### НФТ-4

Система должна корректно обрабатывать ситуацию, когда пользователь добавил мало продуктов.

### НФТ-5

Система должна показывать пользователю понятные сообщения об ошибках.

### НФТ-6

База рецептов должна поддерживать расширение без полной переработки приложения.

### НФТ-7

Приложение должно сохранять стабильную работу при одновременном использовании большим количеством пользователей.

### НФТ-8

Карточки рецептов должны быть визуально единообразными и читаемыми.
